ShirleyOS 專案目前架構與系統能力分析報告

深入探討 ShirleyOS 的「CPU 架構與硬體平台嚴格分離」設計哲學、核心子系統架構、統一裝置與 VFS 抽象、檔案系統支援（exFAT / ext4 / SHRFS1）、UEFI 開機引導與整體系統能力。

01 專案概觀與設計哲學

ShirleyOS 不是教學或玩具性質的研究型微核心，而是一套為了部署在實體機器與虛擬化環境、具備高維護性與高效能而設計的作業系統。

專案最根本的核心原則是「CPU 指令集架構 (ISA)」與「硬體機器平台 (Platform)」的嚴格分離。傳統作業系統常將架構與平台代碼混雜在同一個目錄（例如將 PC 特有的 PIC/PIT 視為 x86 的一部分，或將 GIC 視為 ARM64 的一部分），ShirleyOS 則在目錄邊界與編譯期徹底切斷此依賴。

核心邊界黃金準則

Apple Silicon 是一個 ARM64 平台，不是一種 CPU 架構。
在 ShirleyOS 中，Apple Silicon 嚴格表示為 arch/arm64 + platform/apple_silicon；目錄結構中嚴格禁止出現 arch/apple_silicon。

04 嚴格邊界與單向依賴哲學

ShirleyOS 最大的架構優勢在於將模組邊界的「不平等式」貫徹到底： 

arch ≠ drivers ≠ device ≠ console ≠ fs

這些不平等式是嚴格單向流動的。系統禁止任何反向或跳級呼叫：

硬體存取單向鏈 合法路徑

Hardware → Driver → device::Device → Registry → Console → VFS / Shell

驅動程式負責將中斷接收到的字元推入環狀緩衝區，並包裝為具名裝置註冊到 shirley::device。

嚴格禁止的反模式 編譯/架構阻止
  • Keyboard IRQ → Shell（禁止鍵盤中斷直接呼叫 shell）
  • VFS → inb/outb（禁止檔案系統存取硬體 I/O Port）
  • Device Manager → 0x60（裝置管理員不知道特定硬體暫存器位址）
  • Console → 8259A（主控台不知道任何 PIC 中斷細節）
唯一命名空間：路徑 (Path)

在核心中，路徑是唯一的物件名稱。/dev 只是裝置註冊表之上的一個 VFS 節點映射（devfs），而不是另一套驅動程式。因此，cat /etc/motd 與 cat /dev/kbd0 在核心中走完全相同的 VFS 系統呼叫路徑。

06 CPU 架構層實作 (arch/)

arch/ 封裝了純粹的 CPU 指令集架構、暫存器狀態與特權級別機制，對外透過 include/shirley/arch.hpp 提供介面。

x86_64 架構實作 x86_64
  • 特權模型：GDT 設定 Kernel/User CS、DS 與 TSS，支援 Ring 0 與 Ring 3 切換。
  • 中斷架構：256-entry IDT、組合語言 interrupt.S 處理所有 ISR 入口並保存暫存器。
  • 虛擬記憶體：4 層分頁表（PML4 → PDPT → PD → PT），實作 memory::AddressSpace。
  • CPU 特性啟用：CPUID 偵測、WP (Write Protect)、NX (No-Execute)、SSE/SIMD。
  • 低功耗待機：閒置迴圈使用 hlt 等待中斷，絕不進行空轉輪詢。
ARM64 (AArch64) 架構實作 ARM64
  • 特權模型：EL1 核心特權與 EL0 使用者特權，透過 eret 切換。
  • 例外架構：2 KiB 對齊的 EL1 例外向量表（exception.S），處理 Synchronous、IRQ、FIQ 與 SError。
  • 虛擬記憶體：4KB Granule Stage-1 Translation Table，支援 48-bit 虛擬位址空間。
  • CPU 特性啟用：MIDR_EL1 解碼、啟用 CPACR_EL1 允許 EL0 存取 FP/SIMD。
  • 低功耗待機：閒置迴圈使用 wfi (Wait For Interrupt)。

08 儲存架構、區塊快取與檔案系統實作

ShirleyOS 的檔案系統架構經歷了重大的現代化躍升，從原本僅有的唯讀 RAM Disk 擴展為具備區塊快取、分割表解析、exFAT 讀寫、ext2/3/4 唯讀的現代化儲存堆疊。

1. SHRFS1 (唯讀根檔案系統) 開機必備

在 CMake 建置時，由 make-rootfs.cmake 將 rootfs/ 目錄打包為位元組陣列，直接連進核心映像。開機時由 RAM Disk 掛載至 /，使系統在無磁碟驅動前即可讀取 /etc/motd、/etc/version 與 /bin/hello。

2. exFAT 檔案系統實作 完整讀寫 (FS-2)
  • 識別：檢查 Boot Sector "EXFAT " 標記與修訂版本。
  • 讀取：支援 Allocation Bitmap、Up-case Table（不分大小寫比對）、連續叢集旗標（NoFatChain）。
  • 寫入能力：支援檔案建立、刪除、改名、目錄建立 (mkdir)、內容寫入與截短 (truncate)。
  • 完整性維護：掛載時設定 VolumeDirty，卸載乾淨時清除，確保崩潰安全性。
3. ext2 / ext3 / ext4 檔案系統 唯讀實作 (FS-3)
  • 相容性識別：超級區塊魔數 0xEF53，嚴格檢查 feature_incompat 與 feature_ro_compat。
  • 尋址支援：同時支援傳統 Indirect Block 與現代 Extent Tree。
  • 大型磁區支援：支援 64-bit 區塊號碼、meta_bg (元資料區塊群組)。
  • 目錄與校驗：線性目錄掃描、htree 雜湊目錄平坦化讀取、metadata_csum 校驗。
  • 驗證強度：通過 Linux e2fsprogs 的 215 個測試映像壓力測試而不崩潰。
4. 底層儲存與快取設施 基礎設施
  • io::BlockCache：以 (device, block) 為鍵的 LRU 區塊快取，支援 Write-Back 與 sync()。
  • 分割表解析：支援 MBR（含延伸分割區與邏輯磁區）與 GPT（GUID 分割表）。
  • 裝置註冊：分割區自動映射為 sda1, sda2 等區塊裝置。
  • 長檔名與編碼：支援 255 位元組檔名、512 位元組路徑，實作 UTF-16LE ↔ UTF-8 轉換。

09 統一裝置抽象模型與 devfs

所有硬體裝置均封裝在 shirley::device::Device 介面下，分為三大類別：

字元裝置 (Character Device)

提供序列化位元組流讀寫。代表裝置：console（主控台）、uart0（序列埠）、null（空裝置）。

區塊裝置 (Block Device)

以固定區塊（通常 512 或 4096 位元組）為單位的隨機讀寫。代表裝置：ram0（記憶體磁碟）、vda/sda（VirtIO 磁碟）。

輸入裝置 (Input Device)

產生事件與字元佇列。代表裝置：kbd0（PS/2 鍵盤），自帶環狀佇列與掃描碼轉換。

devfs 將裝置註冊表直接掛載在 /dev 目錄下。每個 VFS 節點僅持有 device::Device* 指標，不需維護重複的狀態。

11 USB 開機安裝程式與測試體系

實體機 USB 可開機安裝程式 (tools/make-usb-installer.sh)

專案具備全自動產出實體 USB 隨身碟映像的能力，可直接寫入隨身碟並在支援 UEFI 的實體 PC 或 ARM 開發板上開機：

  • 標準分割佈局：GPT (GUID Partition Table) 分割表。
  • EFI 系統分割區 (ESP)：FAT32 格式，包含 /EFI/BOOT/BOOTX64.EFI (x86_64) 或 /EFI/BOOT/BOOTAA64.EFI (ARM64)。
  • 系統核心與根目錄：包含 /shirleyos.elf 核心映像與說明文件。
  • 跨平台產出：支援在 Linux 與 macOS 上使用 dd 寫入實體隨身碟，並可在 QEMU 中透過 tools/test-usb-installer.sh 驗證。

13 總結與未來演進路線圖

ShirleyOS 目前已經達到極為穩固的「可操作、可除錯、具備現代化儲存與使用者空間」的里程碑狀態：

  • 系統具備嚴格清晰的層級邊界，在同一個通用核心邏輯下無縫驅動 x86_64 與 ARM64 兩種架構。
  • 具備現代儲存堆疊：不再侷限於 RAM Disk，已可透由 VirtIO 磁碟掛載真實磁碟映像、解析 GPT/MBR 分割表，並支援 exFAT 讀寫與 ext4 唯讀。
  • 具備標準化 UEFI 開機載入器與完整的 USB 安裝程式產出工具鏈，已具備推向實體 PC 開機的能力。
  • 擁有獨立的使用者空間世界：開機直達 PID 1 /bin/init 使用者空間 Shell，使用者與核心透過清晰的 17 個 Syscall ABI 進行互動。

未來演進優先級建議 (Next Steps)

1. 多工排程與行程管理

將目前的單一前台行程延伸為具備搶佔式定時器滴答排程（Preemptive Scheduler）、fork() / waitpid() 支援與行程狀態機。

2. 實體機原生儲存控制器

在 VirtIO 之外，引入 PCI AHCI (SATA) 或 NVMe 驅動程式，讓實體電腦從 USB 開機後能直接讀寫本機固態硬碟。

3. SMP (多核心處理器) 支援

解析 ACPI MADT (x86_64) 或 FDT CPU 節點 (ARM64)，透過 IPI (Inter-Processor Interrupt) 喚醒 Application Processors (AP)。
